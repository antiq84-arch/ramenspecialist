# Snelle Prijs → n8n → Monday lead synchronization

## Outcome

A lead is shown a success screen only after n8n confirms that the data was accepted. n8n creates or updates the client in the Monday group `Cold Leads`, then returns a stable lead ID to the calculator.

## Flow

1. Snelle Prijs validates required fields in the browser.
2. Browser sends one JSON payload to the production n8n webhook.
3. n8n validates consent, phone/email and required configuration fields.
4. n8n normalizes phone, email, language, UTM data and price values.
5. n8n searches Monday for the same normalized phone or email.
6. If found, update the existing item and append the new calculation.
7. If not found, create a new item in the `Cold Leads` group.
8. Set status to `New — call required` and assign the responsible manager.
9. Notify the manager.
10. Return HTTP 200 with `{ "ok": true, "leadId": "..." }`.
11. Only then display the success screen.

On timeout or error, preserve the entered data and show a retry/contact option. Never display success after a failed request.

## Monday field mapping

| Monday field | Calculator value |
|---|---|
| Item name | First name + last name |
| Status | New — call required |
| Group | Cold Leads |
| Phone | Normalized Belgian/international phone |
| Email | Email |
| Municipality | Municipality/postcode |
| Preferred contact | WhatsApp / email / phone |
| Language | NL / FR / EN |
| Source | Google / Meta / referral / direct + UTM |
| Project type | House / apartment |
| VAT indication | Renovation candidate / new build |
| Product level | Budget / Optimaal / Maatwerk |
| Products | Counts by window, door and sliding type |
| Configuration | Profile, glass, colour, ventilation, shutters, extras |
| Indicative range | Low and high, including selected VAT display |
| Timing | Planned project timing |
| Notes | Customer notes |
| Consent | Boolean + timestamp + privacy version |
| Lead origin | Snelle Prijs |
| Created at | ISO timestamp |
| Technical ID | UUID generated by n8n |

## Deduplication

Use normalized phone as the primary key and normalized email as fallback. A returning customer must not create a second cold lead. Update the existing item and append a timestamped calculation summary.

## Minimum statuses

- New — call required
- First call attempted
- No answer
- Contacted
- Qualified
- Appointment planned
- Quote in preparation
- Quote sent
- Won
- Lost / not relevant

## Security

- Pricing coefficients and supplier prices stay in n8n/server-side logic.
- The public browser receives only the calculated result.
- Webhook rejects requests without required fields and consent.
- Add rate limiting, honeypot and origin checks.
- Do not place Monday credentials in HTML.
- Do not log unnecessary personal data.

## Social proof

Use verified backend data only. Recommended display:

- Before 25 completed calculations: `Gratis prijsindicatie · Vrijblijvend · Antwoord binnen 24 uur`.
- From 25 onward: `Al {verified_count} prijsberekeningen gemaakt`.
- Optional real recent activity: `Laatste aanvraag {time_ago}`, only when a real consented event exists.

Never generate random online visitors, requests or timestamps.
